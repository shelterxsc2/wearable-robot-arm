## 二、关键发现与结论

### 1. 左右不对称的根因
- `YAW_OFFSET = +0.03 rad`（+1.7°）是单向偏移
- 导致右转有效误差 ≈ 左转的 2 倍
- **修复**：清零 `YAW_OFFSET`

### 2. 死区是决定稳定性的核心
- 死区 2° 时：噪声（±1~2°）被当成有效信号，P 项每帧跳变，系统高频 oscillate
- 死区 5° 时：明显好转，人正视时的微动被过滤
- 死区 6° 时：进一步改善，配合 KI=0.040 测试效果待验证

### 3. PI vs 纯积分的权衡
- **纯积分**：慢但稳，无过调，最终能对准
- **PI（KP=0.9）**：P 项加速响应，但放大了 PnP 噪声，在小死区下导致抖动
- **结论**：PI 可用，但必须有足够大的死区（≥5°）过滤噪声

### 4. 运动生硬问题
- 表现为"从运动到停止太硬"
- 判断为**下位机缺少轨迹规划/速度平滑**
- 上位机不处理，待下位机优化

### 5. PnP 噪声水平
- 人脸正视时 `head_yaw` 波动约 ±1~3°
- 俯仰方向 `head_pitch` 波动约 ±0.5°
- 这是死区设计的基准线

## 四、下一步工作（按优先级）

### P1：基础设施（先做完再调参）

#### 1. 日志对齐 —— 只打印发送帧，P/I 分离显示
**问题**：当前每帧都打印，90% 日志是中间过程，无法对应机械臂实际动作  
**方案**：把 `VERIFY` 打印移到 `if (uart_send_cnt % 10 == 0)` 分支内，格式：
```
[TX] yaw_in=5.2° P=2.7° I=1.8° out=4.5° pitch_in=25° P=42° I=20° out=60° → target(x,y,z)
```

#### 2. PID 框架化 —— 抽离为可调结构体
**问题**：PID 参数散落在 `rga_npu.cpp` 各处，改一个数要重新编译  
**方案**：
- 定义通用 `PID` 结构体（含 Kp/Ki/积分限幅/输出限幅/死区）
- 偏航、俯仰复用同一套结构
- 支持运行时从 `/tmp/pid.conf` 热加载参数

#### 3. 数据记录 —— 按发送周期写 CSV
**目的**：事后用 Python 画响应曲线，定量看超调/调节时间  
**字段**：`time_ms, head_yaw, head_pitch, yaw_p, yaw_i, yaw_out, pitch_p, pitch_i, pitch_out, target_x, target_y, target_z`
