# 机械臂控制系统 — 项目理解与架构说明

> 本文档由 AI 助手基于完整代码阅读整理，覆盖上下位机全部源码、SDK 架构、控制算法与机械结构。

---

## 1. 项目概述

本项目是一套**可穿戴机械臂视觉伺服系统**，核心功能为：RK3588 上位机通过 USB 摄像头实时检测人脸/人体姿态，经 NPU 推理和 PnP 位姿估计后，通过 UART 向下位机 STM32H723 发送目标空间坐标，STM32 通过逆运动学、S 曲线速度规划和 MIT 力矩控制驱动三个关节电机，实现相机对人脸的实时跟踪。

```
┌─────────────────────────────────────────────────────────────────────────┐
│                         上位机 (Host) — RK3588                          │
│  USB摄像头 → RGA硬件预处理 → NPU推理(RKNN) → PnP位姿估计 → UART发送   │
│  ├─ GStreamer RTSP推流                                                  │
│  ├─ WiFi / 蓝牙 BLE                                                      │
│  └─ WebSocket连云                                                        │
└─────────────────────────────────────────────────────────────────────────┘
                                    ↕ UART (USART1 / ttyS9)
┌─────────────────────────────────────────────────────────────────────────┐
│                      下位机 (MCU) — STM32H723 @ 480MHz                  │
│  UART DMA接收 → 逆运动学 → S曲线规划 → MIT控制+重力补偿 → FDCAN发送    │
│  ├─ FDCAN1: LK4005 ×3 (云台+大臂+小臂)                                  │
│  ├─ TIM: LFD01M舵机 ×2                                                  │
│  └─ SPI2: BMI088 IMU (预留未使用)                                        │
└─────────────────────────────────────────────────────────────────────────┘
```

### 2.3 电机系统（当前配置）

| 索引 | 关节 | 型号 | FDCAN | ID | 控制模式 | 传动比 |
|------|------|------|-------|-----|---------|--------|
| `[0]` | 云台 | LK4005 | FDCAN1 | `0x14C` | 位置控制 (`0xA3`) | 1:1 |
| `[1]` | 大臂 | LK4005 | FDCAN1 | `0x143` | MIT力矩 (`0xA1`) | **2:1** |
| `[2]` | 小臂 | LK4005 | FDCAN1 | `0x149` | MIT力矩 (`0xA1`) | **2:1** |

> **历史变更**: 大臂原使用 DMJ4310 (达妙电机，MIT协议)，已迁移至 LK4005。三个电机现统一在 FDCAN1 总线上。

### 2.4 LK4005 电机协议

| 命令字节 | 功能 | 数据格式 |
|---------|------|---------|
| `0xA1` | 力矩控制 | DATA[4:5] = int16 力矩值 (Torque×62.0606) |
| `0xA3` | 位置控制 | DATA[4:7] = int32 位置值 (deg×100×10) |
| `0x92` | 读取多圈位置 | 回复: DATA[1:7] = int64 motorAngle (0.01°/LSB) |
| `0x9C` | 读取速度 | 回复: DATA[4:5] = int16 速度 (0.01°/s) |

### 2.5 核心算法

#### S 曲线速度规划 (Speed_Plan_Update)

7 段式加减速状态机，**自适应参数**（短距离优化）：

```
phase1:  j↑ 加加速度上升 → a 达到 a_limit
phase2:  a 匀加速 → v 接近 v_limit-v1
phase3:  j↓ 加加速度下降 → a 归零，v 达到 v_limit
phase3_end/phase4: 匀速巡航 → 判断减速距离
phase5:  j↓ 减减速度 → a 达到 -a_limit
phase6:  a 匀减速 → v 降至 v1
phase7:  j↑ 加减速度 → a 归零，v 归零
```

**自适应特性**（短距离时自动降低参数）：
- `S < 0.03m`: `v_limit × 0.15`, `j_limit = 6.0`
- `S < 0.06m`: `v_limit × 0.20`, `j_limit = 8.0`
- `S < 0.15m`: `v_limit × 0.30`, `j_limit = 10.0`

#### MIT 控制

```
Output = Kp × (位置误差) + Kd × (速度误差) + 前馈力矩 + 摩擦力补偿
```

| 关节 | Kp | Kd | 摩擦补偿 |
|------|-----|-----|---------|
| 大臂 | 67.8 | 1.73 | 0.02 N·m |
| 小臂 | 100.5 | 2.05/1.45 | 0.02 N·m |

#### 重力补偿

- **大臂**: 补偿大臂自身重力 + 小臂/末端等效重力
  ```c
  Upperarm_Gravity_Compensation(upper_angle, fore_angle)
  ```
- **小臂**: 仅补偿小臂和末端重力
  ```c
  Forearm_Gravity_Compensation(upper_angle, fore_angle)
  ```

> 重力补偿公式基于余弦定理，当前使用**电机轴角度**（未做 ÷2 修正，齿轮传动比的修正待后续实现）。

#### 逆运动学 (Coordinate_Inverse_Settlement)

输入: `(X, Y, Z, Servo_Angle)` — 单位 m, rad  
输出: `(Gimbal_Angle, Joint_Upper_Angle, Joint_Fore_Angle)` — 单位 rad

使用余弦定理求解双连杆机构，包含舵机虚拟长度修正（`L2_Length_Virtual`）。

### 2.6 启动流程

当前启动顺序（三级状态机）：

```
阶段0: 云台先启动
  └─ 云台到位前：大臂[1]和小臂[2]锁定当前位置
  └─ 云台到位后 (Gimbal_Start_Complete = 1)
      └─ 设置大臂目标 = -0.605f，Gimbal_Start_Complete = 2

阶段1: 大臂启动
  └─ 大臂到位前：小臂[2]锁定当前位置
  └─ 大臂到位后 (Joint_Upper_Start_Complete = 1)
      └─ 设置小臂目标 = 1.67f，Joint_Upper_Start_Complete = 2

阶段2: 小臂启动
  └─ 小臂到位后 (Joint_Fore_Start_Complete = 1)
      └─ Joint_Fore_Start_Complete = 2，全部启动完成
```

> **锁定位置机制**: 在 Wait_Count ≥ 15 时，将当前 `Motor_Position_Actual` 赋值给 `Motor_Position_Target`，使电机保持静止。

## 3. 上位机 (Host — RK3588)

### 3.1 硬件平台

- **SoC**: Rockchip RK3588 (4×A76 + 4×A55)
- **NPU**: 6 TOPS INT8 算力
- **RGA**: 2D 硬件图形加速
- **摄像头**: USB Camera (Realtek, 2.7mm 130° 广角)

### 3.2 核心视觉链路

```
USB Camera (YUYV 1920×1080)
    ↓
RGA硬件: YUYV → NV12 + resize 640×640
    ↓
NPU推理 (RKNN): 双模型切换
    ├── FACE模式: face_best.rknn → 6个关键点
    │   (双眼、鼻尖、嘴角、下巴 → 用于 PnP)
    └── BODY模式: best.rknn → YOLOv8n-pose 17个COCO关键点
    ↓
FaceTracker: 10帧滑动窗口 + IoU匹配
    ↓
OneEuro滤波器: 按关键点类型分级滤波
    ├── 弱关键点 (0,1,2,17,18,19): mincutoff=1.2, beta=0.015
    └── 强关键点: mincutoff=0.8, beta=0.008
    ↓
PnP位姿估计 (solvePnP): 6个3D点 → rvec/tvec
    ↓
α坐标系变换: 头部坐标系 → 机械臂基座坐标系
    ↓
绘制: 3D立方体重投影 + 姿态指示器 + 文字叠加
    ↓
GStreamer RTSP推流
```

### 3.3 PnP + α 坐标系变换

**3D 人脸模型**（单位 mm，基于 P50 男性头面部数据）：
```cpp
{-30,-25,-60}  // 右眼
{ 30,-25,-60}  // 左眼
{  0, -5,-90}  // 鼻尖
{-25, 20,-65}  // 右嘴角
{ 25, 20,-65}  // 左嘴角
{  0, 50,-40}  // 下巴
```

**坐标变换**: OpenCV 相机坐标系 → α 坐标系（机械臂基座系）
```
R_af = [ 1  0  0 ]      // X_f(右) → X_a(右)
       [ 0  0 -1 ]      // Y_f(下) → -Z_a(下)
       [ 0 -1  0 ]      // Z_f(前) → -Y_a(后)

t_cam_in_alpha = R_af × R_obj2cam × (t_cam_in_obj - d_O_in_head)
```

### 3.4 与下位机通信

**当前实际使用的格式**（10 字节原始格式）：
```
[ x_L ][ x_H ][ y_L ][ y_H ][ z_L ][ z_H ][ k1_L ][ k1_H ][ k2_L ][ k2_H ]
  int16小端, 单位 cm              int16小端, 单位度
```

**设计中的标准帧格式** (`shared/protocol.h`，尚未被 STM32 采用）：
```
[0xAA][0x55][LEN][CMD][payload...][CRC8]
```

| CMD | 功能 |
|-----|------|
| `0x01` | 心跳/握手 |
| `0x10` | 上位机→下位机: 目标位姿 Pose6D (28字节 float) |
| `0x20` | 下位机→上位机: 当前位姿 |
| `0x30` | 上位机→下位机: 简化指令 (x,y,z,k1,k2) |

### 4.2 绳控 + 齿轮连杆传动方案

**关键设计**: 大臂和小臂的关节处各有一对同规格齿轮（半径、齿数相同），通过**齿轮连接杆**传动。

```
云台基座 ──[直驱]── 大臂 ──[齿轮连杆 2:1]── 大臂电机(LK4005)
                     │
                     └──[齿轮连杆 2:1]── 小臂电机(LK4005)
```

**数学关系**:
```
电机角度 = 关节相对角度 / 2
关节相对角度 = 2 × 电机角度
```

| 关节 | 传动方式 | 电机角度 vs 关节角度 |
|------|---------|---------------------|
| 云台 | 直驱（无变化） | 1:1 |
| 大臂 | 绳控 + 齿轮连杆 | **1:2**（电机 = 关节/2）|
| 小臂 | 绳控 + 齿轮连杆 | **1:2**（电机 = 关节/2）|
| 舵机 | 无变化 | 1:1 |

> **代码状态**: 齿轮传动比（÷2/×2）的代码修正**尚未实施**，当前逆运动学输出、电机反馈、重力补偿中均直接使用电机轴角度。后续需统一修正。

### 4.3 角度偏移

| 关节 | 偏移量 | 说明 |
|------|--------|------|
| 云台 | `Angle_Gimbal_Offset = 0.75 rad` | 电机测得角度比实际大 |
| 大臂 | `Angle_Joint_Upper_Offset = 0.07 rad` | 电机测得角度比实际大 |
| 小臂 | `Angle_Joint_Fore_Offset = -0.18 rad` | 电机测得角度比实际小 |
| 舵机1 | `Angle_Servo_Offset = 0.4 rad` | 与小臂相连的舵机 |

## 5. 通信协议细节

### 5.1 下位机 UART 接收（当前实现）

`Robotic_Arm_Communication_HAL_STM32_Port.c` 中 `HAL_UARTEx_RxEventCallback`：

1. **一阶低通滤波**: `ALPHA = 0.65`
2. **死区判断**:
   - 位置死区: `POS_DEADZONE_M = 0.015f` (1.5 cm)
   - 舵机1死区: `SERVO1_DEADZONE_RAD = 0.05f` (~2.9°)
3. **逆运动学解算**: `(X,Y,Z,Servo2) → (Gimbal, Upper, Fore)`
4. **触发 S 曲线规划**: 三个电机 `Speed_Plan_State = init`

### 5.2 测试模式

`Test_Mode_Active = 1` 时（默认开启）：
- 屏蔽上位机 UART 指令
- 自动执行四角循环测试（10 轮）
- 测试点: `(±0.02, 0.70, 0.42/0.38)` m，舵机固定 90°

## 8. 已知问题与待办

1. **齿轮传动比未修正**: 大臂/小臂的 ÷2/×2 逻辑尚未在代码中实施（逆运动学输出、电机反馈、重力补偿均需修改）。
2. **通信协议不匹配**: `shared/protocol.h` 定义了标准帧格式 `[0xAA][0x55]...[CRC8]`，但 STM32 实际使用 10 字节 raw 格式（无帧头、无 CRC）。
3. **IMU 预留未使用**: `BMI088_IMU_Driver` 仅空壳头文件。
4. **上位机 PnP 滤波已禁用**: `PNP_USE_FILTER = 0`（OneEuro 滤波关闭）。
5. **蓝牙 SPP 临时禁用**: `host-rk3588/main.cpp` 中注释掉了蓝牙初始化。
6. **手眼标定缺失**: RK3588 端缺少精确的 `T_end←camera` 变换矩阵。
7. **STM32 → RK3588 回传未实现**: `CMD_CURRENT_POSE (0x20)` 定义了但 STM32 未发送。
